## 1. Shortcut / Host Adapter

Project scope 的可攜性規則現在是硬性 invariant：

```text
project scope -> repo-context ...
global scope  -> repo-context if available; otherwise machine-local runtime fallback allowed
```

已提交的 `.claude/commands/` 與 `adapters/codex/` 仍保留作 GitHub 上可讀 snapshot，但測試會逐字比對 renderer；因此它們不再是可自由手改的第二、第三份事實來源。

## 2. State 與 Cache

v1.4 統一使用：

```text
.repo-context/
├── index.json
├── cache/summaries-v3.json
├── sessions/
├── runs/
├── artifacts/
└── ...
```

舊 `.repo-context-cache/summaries-v2.json` 可被讀取並在後續 save 時遷移。所有 state writer 走共用 state-directory helper，以統一 `.gitignore` 行為。

## 3. Sync 語意

`sync` 在 v1.4 的精確契約是：

- unchanged source structural summaries 可以由 cache 重用；
- repository file enumeration 會重新執行；
- dependency graph 會重建；
- ranking 會重建；
- persistent index JSON 會重寫。

因此它是 **cache-aware refresh**，不是 fully incremental graph maintenance。`--no-sync` 則嚴格代表「只使用已存在 index」，沒有 index 時直接失敗。

## 4. Capability Manifest

`capabilities.json` 不再手工維護。Runtime 內的 capability set 與分類是 canonical source，開發者可執行：

```bash
python3 scripts/generate_capabilities.py
```

測試會驗證 committed manifest 與 runtime 產生結果完全一致。

## 5. CLI 拆分

v1.0 的 `cli.py` 同時負責 argparse、business wiring、context orchestration 與 repository handlers。v1.4 拆成：

```text
cli.py                 thin dispatch / output / errors
cli_parser.py          argparse definitions
context_command.py     provider-aware context orchestration
repository_commands.py map/query/deps/impact handlers
index_runtime.py       persistent-index helper
repository_runtime.py  inspect/symbol helper
```

此重構保留既有 CLI surface，不要求使用者遷移指令。

## 6. 產品邊界

v1.4 明確定義：

- **Core Reducer**：真正處理 repository context 的預設產品。
- **Optional Advisory Harness Planner**：complexity/risk/model-tier/lane/grader/retry 的建議層。

Advisory Planner 不會自行 spawn agents 或切換模型；執行仍需要 host/runtime/provider 支援。這避免讓使用者誤以為安裝 Reducer 就自帶完整 multi-agent executor。

## 7. 未宣稱已完成的事

本次**沒有**把 cache-aware refresh 改寫成真正 incremental graph algorithm，也沒有宣稱 runtime call graph、GraphRAG、或 universal agent read interception。這些仍屬不同能力邊界，不應用文件措辭掩蓋實作差異。

## 驗證

正式發佈前必須至少通過：

```bash
python3 -m unittest discover -s tests -v
python3 scripts/generate_capabilities.py
python3 scripts/repo_context.py --version
```

以及 Host snapshot / project portability / manifest consistency / state-ignore / `--no-sync` regression tests。
