# v2.0 Runtime Integration Audit

Date: 2026-08-17

## Closed gaps

- Scheduler output can now be executed through an explicit adapter surface.
- Independent waves run concurrently with a hard concurrency bound.
- Retry/tier escalation, cancellation/backpressure and grader gating affect execution rather than existing only as advisory JSON.
- Repository context is sliced per lane instead of copied wholesale into every worker invocation.
- Fan-in synthesis evidence is delivered to grader/integrator before their calls.
- Token/latency telemetry is persisted and cost provenance is explicit.
- Subprocess stdout is bounded during execution.

## Deliberate limits

- The native subprocess adapter is not a security sandbox and does not isolate descendant processes, filesystem or network access.
- Core model tiers are vendor-neutral; adapters map tiers to real models.
- Concurrent calls can overshoot aggregate token limits before cancellation propagates.
- Final-answer invariant checks do not prove semantic correctness.
- No webhook/background worker service is included; runtime execution is synchronous from the caller's perspective.

## Release gate

The v2.0 release must pass the full historical regression suite, runtime-specific tests, the real subprocess example, schema validation, wheel build, and clean-environment installation smoke tests.
