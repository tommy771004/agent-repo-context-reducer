# v2.1 Sandbox & Durable Runs Audit

## Closed gaps

- v2.0 subprocess cancellation targeted the direct child; v2.1 uses process-tree semantics.
- v2.0 documented the lack of a sandbox; v2.1 adds an optional hardened container adapter.
- v2.0 runtime state was observable but not resumable; v2.1 adds atomic checkpoints and resume.
- v2.0 had no source-drift gate for resumed work; v2.1 adds bounded Git working-state identity.
- Container image pulling could otherwise bypass the intended worker network policy; v2.1 defaults to `pull=never` and requires network authorization for pull.

## Remaining boundaries

- Container isolation is not a VM security guarantee.
- In-process host adapters still rely on cooperative cancellation.
- Checkpoints are single-controller durable state, not a distributed lock/consensus service.
- Non-Git repositories cannot receive cryptographically strong whole-repository drift detection without an additional scan cost.
- Runtime providers remain responsible for concrete model credentials, API safety and reported billing metadata.
