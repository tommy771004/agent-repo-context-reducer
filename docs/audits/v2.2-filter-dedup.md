# v2.2 Filter & Dedup Design Audit

## Iterative findings fixed

1. Same-worker repetition inflated historical occurrence semantics -> agreement now counts unique workers only.
2. String assertion values could collapse under one canonical fact -> scalar string/bool/number sides are structured.
3. Candidate merges were reported but not applied -> deterministic verified second pass added.
4. Candidate-merge statistics could remain pre-merge -> final metrics are recomputed.
5. External exact content across different files could collapse -> merge authority now includes location identity when present.
6. Pair-wise safe unions could create transitive identity/assertion conflicts -> component guard added.
7. An identity-less bridge could attach to whichever conflicting side was processed first -> global candidate-graph ambiguity guard added.
8. A higher-confidence identity-less representative could erase canonical/value metadata -> unambiguous fields are promoted from support.
9. Recursive handoff list dedup could alter event/step sequences -> only set-like top-level fields are deduped.
10. Contradiction sides were duplicated in synthesis findings -> conflict identity is represented once in mandatory contradictions.
11. Batch diagnostics were unbounded while streaming was bounded -> both paths now enforce detail limits.
12. Filter token savings counted reducer-added trust metadata -> savings use raw input item estimates.
13. Same-identity candidate generation could allocate O(n²) pairs -> bounded identity-first candidate generation.
14. Optional synthesis metadata pushed useful findings out of small budgets -> unavailable counters are omitted.
15. Draft 2020-12 validation caught a measurement string inside integer-only `token_savings` -> contract/runtime shape corrected.

## Validation gates

- Historical unit/regression suite.
- Adversarial canonical/assertion/bridge cases.
- Randomized batch-vs-stream semantic parity with invariant audits.
- Bounded 5,000-item same-identity candidate stress test.
- Main CLI batch, NDJSON, negative audit/exit-code smoke.
- All formal schemas checked as Draft 2020-12 and representative fan-in/audit/synthesis payloads validated.
- Clean wheel installation and installed CLI smoke are required before packaging.

## Remaining boundaries

- Filter audit proves internal consistency, not semantic truth.
- `legacy-merge` can intentionally group differently worded unstructured claims and therefore emits warnings.
- Unique-worker agreement is not a statistical independence proof; `independent_evidence_count` is reported separately.
- Host semantic candidate providers must honor `max_pairs`; they never obtain merge authority.
- Existing container sandbox is not a VM and distributed run locking is not part of v2.2.

## Token-amplification audit additions

16. Rich reducer metadata was initially eligible to leak into model requests -> Thin Model Context and Thin Model Packet sidecars now separate control/data planes.
17. Grader/integrator received synthesis plus another general repository lane -> grader context is source-targeted and integrator is synthesis-only.
18. Early scenario projections incorrectly credited local dedup only to Light -> deterministic filtering now applies to Direct/Light/Full equally.
19. Light appeared cheaper by giving its worker less evidence -> adaptive lane budgets now reallocate synthesis-role repository budget back to evidence workers while preserving the aggregate ceiling.
20. Runtime routing initially used fixed token thresholds instead of the economics model -> the router now projects every eligible mode after safety filtering.
21. Pre-run routing did not propagate `multi_agent_recommended` -> it now becomes a parallel-evidence requirement and forces Full.
22. Provider-reported pipeline tokens could be compared with an estimated baseline without warning -> token economics now marks this `mixed-measurement` and disables a precise savings claim.
23. CLI parser/dispatch behavior and simulation assumptions are exercised through a standalone release gate in addition to unit tests.

### Calibrated scenario result

The seven-scenario deterministic suite currently projects Direct 110,262, Light 115,847, Full 129,201 and Adaptive 123,936 aggregate model tokens. Adaptive is 5,265 (4.08%) below always-Full. Static Direct is lower but is not globally eligible; using it in high-risk/conflicting cases would violate the routing safety contract. These values are simulation assumptions, not provider billing or answer-correctness measurements.

### Release usability gate

`scripts/release_gate.py` requires 26 schemas, filter invariants, thin packet/context reduction, source-targeted grader context, synthesis-only integrator context, Low/Medium/High -> Direct/Light/Full routing, all three modes in the scenario suite, Adaptive <= always-Full, and honest mixed-measurement labeling.
