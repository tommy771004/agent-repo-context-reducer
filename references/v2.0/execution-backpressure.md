# v2.0 Execution, Backpressure and Cancellation

The runtime consumes the dependency waves generated by the deterministic scheduler. Only nodes in the same dependency-ready wave can run concurrently.

Backpressure is enforced at runtime, not merely reported:

- maximum worker concurrency;
- aggregate model-call limit;
- aggregate input/output token counters;
- wall-clock deadline;
- fail-fast cancellation when configured;
- direct-child subprocess termination on cancellation/timeout/oversized output.

Independent workers may finish concurrently and therefore can create bounded overshoot around token limits. The runtime records observed usage and stops later work; it does not claim transactional quota enforcement across already-running provider calls.

Retries are bounded by the existing retry policy. After the allowed same-tier retry count, the abstract tier may escalate (`cheap -> standard -> strong`). The runtime adapter decides how that abstract tier maps to a real provider/model.
